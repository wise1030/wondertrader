# 评估：failStreak 与成交价偏离是否应作为 Panic 源（2026-11-25）

> 背景：v4 panic 重构后触发源为三支——pricerPanic（毒性/PnL 信号）、checkerPanic（成交价偏离 FillPriceChecker）、failStreak（降险失效门）。用户质疑：**Panic 应对市场极端行情、暂停后可恢复、由 panic 信号驱动——failStreak 与成交价偏离是否属于此类？** 本文评估。**未改代码。**

---

## 1. Panic 的本质约束（从原版语义提炼）

一个合格的 panic 源必须同时满足三个性质：

| 性质 | 含义 |
|------|------|
| ① **外生性** | 触发根源是**市场环境**（行情/微结构），不是账户/策略的内部状态 |
| ② **可恢复性** | 环境恢复后自动退出——"暂停-恢复"循环成立（电平驱动：信号在阈上持续 panic，回落即恢复） |
| ③ **暂停的合理性** | 暂停报价能**降低损失**（市场极端下继续报价=继续被逆选）；而不是"放弃业务"（报价本身无害甚至有益） |

原版 PanicSignal（lua 可配置）由运营定义市场异常——天然满足三条。

## 2. 逐源评估

### 2.1 pricerPanic（毒性流 / PnL 信号）—— ✅ 保留

- 毒性流：市场行为极端（逆向选择密度），继续报价持续亏损 → 暂停合理；blackout 后环境恢复自动恢复 ✓ 三条全满足。
- PnL 信号：当日亏损触限——半外生（市场导致），暂停避免扩大 ✓。
- **结论：保留**（这就是原版 PanicSignal 的移植）。

### 2.2 checkerPanic（成交价偏离 FillPriceChecker）—— ✅ 保留

- 触发含义：我们的挂单以**显著偏离发出价的价格成交**——根源是行情瞬间跳变/盘口被掏空/**定价或行情数据异常**。
- ① 外生性 ✓（价格跳变是市场行为；定价错误也是"环境不可信"）；② 可恢复 ✓（blackout 后跳变已过，坏成交不再出现——电平驱动）；③ 暂停合理 ✓（定价或行情不可信时继续挂单=继续暴露于坏成交）。
- **结论：保留**。它是原版"市场异常信号"的一个具体化实例（把"波动跳变"换成了更直接可测的"成交价 vs 报价偏离"），语义一致。

### 2.3 failStreak（降险失效门）—— ❌ 应移出 panic 源

**逐条检验三条性质，全部不满足**：

| 性质 | failStreak 的现实 |
|------|-------------------|
| ① 外生性 ❌ | 触发根源是**账户/运营状态**（SimNow 资金枯竭 → 买入降险单被 error-31 拒；riskmon 排除；涨跌停），不是市场极端行情 |
| ② 可恢复性 ❌ | "恢复条件"=降险成交成功——取决于资金与市场流动性，**可能长期不满足**（vega 遗留库存 + 无资金 = 永不恢复）。违背"暂停-恢复"循环：这不是暂停，是停机 |
| ③ 暂停的合理性 ❌ | 降险失效的根源是资金/限位，**停掉做市报价不解决任何问题**：风险还在、降险依旧做不了，还放弃了正常做市的点差收益。双边报价本身是健康业务 |

** failStreak 的正确归宿：持续的运营告警状态，不是 panic。** 它与 RiskLimitsEx 的 max_vega 超限同类——都是"需要人工介入的持续风险状态"，正确的响应是：告警（UI Alert/横幅）+ 已有的期货兜底 + 方向性抑制（保降险边、停增险边），**报价继续**。

（注：v4 设计时把 failStreak 放进 panic 源的理由是"逼人工处置"——但 panic 并不能逼出资金，只会把业务也停掉；告警+兜底同样能提示人工，且不牺牲业务。评估后放弃该理由。）

### 2.4 边界情形辨析

- "降险失效 + 行情同时极端"：行情极端本身会由 pricerPanic（毒性）触发——不需要 failStreak 参与。
- "资金枯竭导致双向都无法报价"：资金层应有自己的告警（HEDGE rejected alert 已有；可扩展连续拒单告警），但不升级为 panic——报价失败是"空转"不是"风险"。
- "降险失败导致风险无限放大"：severity 攀升由 RiskLimitsEx 持续告警 + 方向性抑制（停增险边）兜住；剩余风险是**存量**而非新增。

## 3. 结论与建议

1. **panic 源收敛为两支**：`pricerPanic`（市场信号）+ `checkerPanic`（成交价偏离）——均满足外生/可恢复/暂停合理三性质。
2. **failStreak 移出 panic**：改为**持续运营告警状态**（首次进入 + 限频重复告警，UI 状态灯），期货兜底与方向性抑制保持现有分级不变。
3. **checkerPanic 保留**（评估通过）。
4. 处置路径：
   - **立即（纯配置）**：`panic_fail_streak_sec` 调大至实际不可达（如 999999）——等效停用 failStreak，夜盘开盘前重启生效，避免 SimNow 无资金下的必然误瘫痪；
   - **代码版（下版本）**：从 panic 块移除 `reduceDead` 分支，failStreak 转独立告警状态（限频 UI Alert），`panic_fail_*` 参数语义同步改为告警参数。
5. 二期（可选）：对标原版 `panic_signal` 的可配置化——把"市场异常"定义做成可配置信号链（毒性/波动跳变/盘口消失），运营按品种调整，替代硬编码的 Toxicity/Pnl 两支。

## 4. 与原版的最终对应

| 原版 | 我们（本评估后） |
|------|------------------|
| `panic_signal`（lua 市场信号）×阈值 → pricer blackout | `pricerPanic`（毒性/PnL 信号）+ `checkerPanic`（成交价偏离）→ pricer blackout（指数退避） |
| blackout 300s 自动恢复 | 同（含指数退避） |
| 期权双边擦除、主月期货腿保留 | 同（panicClear 期货 live） |
| scanners 静默 | 同（v4 P1d 已实现） |
| 持仓风险 → risk shift + alpha 硬限 + DeltaHedger | 同（risk shift 已上线 + 方向性抑制 + 期货兜底）+ failStreak 告警（新增，不进 panic） |
