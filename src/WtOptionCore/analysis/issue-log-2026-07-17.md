## 一、P0 — 正确性硬伤（必须修复才能实盘）

### P0-A: SPSC 队列多生产者 — 未定义行为
- **位置**: `OptionAsyncEventProcessor.h:158-159` (boost::lockfree::spsc_queue<4096>)
- **根因**: spsc_queue 假设单生产者（注释 h:154-157），但实际两个生产者线程并发 push：
  - T1 行情线程: `enqueue_tick` (HftOptionStrategy.cpp:1642)
  - T2 交易回报线程: `enqueue_trade/order/position/channel` (1658/1669/1681/1695)
- **影响**: boost spsc_queue 并发 push 是 UB → 事件丢失/内存损坏
- **方案**: **双 SPSC 队列**（md 队列 + trader 队列，worker 轮询两个）
  - `OptionAsyncEventProcessor` 新增 `_md_queue` + `_trader_queue`
  - `enqueue_tick/timer` → md_queue；`enqueue_trade/order/position/channel` → trader_queue
  - `worker_loop` 先 drain md_queue，再 drain trader_queue，合并到同一 batch
  - 两个 SPSC 队列各自无锁，worker 单消费者
- **严重度**: 🔴 最高危（高频系统底层线程模型错误）

### P0-B: OptionPricer2 单边 strike 空指针段错误
- **位置**: `OptionPricer2.cpp:552-553`
- **根因**: `m_grid->get(exp, strike, otherRight)` 取对侧腿未判空，直接 `->values()`。动态发现期间单边 strike（put tick 未到）→ segfault
- **影响**: gammascalp 路径必然暴露（GammaScalpOptionPricer.cpp:105 直接调 OP2::computeValues）。composite_mm 路径免疫（COP 先判空 L415）
- **方案**: OP2 `__doComputeValueStrikeVec` 与 SLOW 循环加 `if (!otm || !itm) continue;`
- **严重度**: 🔴 高

### P0-C: 平仓报价被 PositionOffsetMgr 静默吞掉
- **位置**: `OptionQuoteManager.cpp:253-276`
- **根因**: PositionOffsetMgr 判定为平仓单时，撤掉旧报价后 `return`，不发新单。注释说"由策略路由 stra_exit_long/short"，但 HftOptionStrategy 无此调用 → **平仓方向报价静默消失**
- **WT ActionPolicy 分析**:
  - `stra_quote` → `TraderAdapter::quote` (TraderAdapter.cpp:1285) → offset **硬编码 WOT_OPEN** (L1293/1299)，**不经过 action policy**
  - `stra_buy/stra_sell` → `TraderAdapter::buy/sell` (L680/L970) → **经过 action policy**，自动按 closeToday→closeYesterday→open 顺序拆分今昨仓
  - 做市策略两条路径:
    - **quote API 模式** (CFFEX 等支持双边报价的交易所): 双边报价 offset=OPEN，交易所成交后自动净仓
    - **非 quote API 模式** (商品期权): 应改用 `stra_buy + stra_sell` 挂限价单，action policy 自动处理 offset
- **方案**: **移除 PositionOffsetMgr 在 OQM 中的拦截逻辑**（删除 L253-276），今昨仓拆分完全由 WT action policy 处理
  - quote API 模式: 直接 stra_quote，交易所自动净仓
  - 非 quote API 模式: OQM::sendQuote 改用 stra_buy + stra_sell（需新增 sendBuySell 分支），action policy 自动拆分
  - PositionOffsetMgr 保留作为持仓监控/对账（PositionGuard 的今昨仓细化），但不在 OQM 发单链路拦截
- **严重度**: 🔴 高（直接打断 auto_close 平仓链路）

### P0-D: 跨月风险对冲配置断链
- **位置**: `CompositeOptionPricer.h:174-177` vs `:408-411`
- **根因**: `hedge_ratio_delta/vega`、`lambda_vega_decay/wing` 4 项配置在 `CompositeOptionPricerConfig` (h:174-177) 声明，但构造函数 (cpp:123-154) **不拷贝到** `m_prop_hedge_ratio_delta/vega` (h:408-411)
- **影响**: 跨 expiry delta 相关项 (cpp:1325) 恒 0、vega 相关 (1434,1453) 恒 0、wing 调整 exp(0)=1。**跨月风险抵消完全关闭**
- **方案**: 构造函数拷贝 4 项配置
- **严重度**: 🔴 高

## 二、P1 — 中等严重（影响功能/性能）

### P1-A: Scanner 框架失效（2 个 bug）
1. **10 个 scanner 仅 1 个注册**: `REGISTER_SCANNER` 仅 SpreadScanner.cpp:135 使用。config 配 Butterfly/Garch/VolSpread 等全部静默加载失败（工厂返回 nullptr，只 log 一行）
2. **enable 判断写反**: `if (!sCfg->has("enable") ? sCfg->getBoolean("enable") : true) continue;` (HftOptionStrategy.cpp:1548) — key 不存在反而去读（可能异常）、存在时恒 true 不 skip
- **方案**: 9 个 scanner 补 REGISTER_SCANNER；enable 判断改 `if (!sCfg->getBoolean("enable")) continue;`

### P1-B: 8/12 热更新参数不落盘
- **位置**: HftOptionStrategy.cpp:434-446 注册 12 个 sync_param
- **根因**: 真正生效仅 4 个（max_tps/command/qmode_override/manual_order）。5 个 alpha 权重 + sticky_base + improve_retreat_ratio + trade_shock_ticks 只 log 不应用——`CompositeOptionPricer::m_config` 是 const 构造期拷贝，无 setter 通路
- **方案**: COP config 改 mutable + 加 applyAlphaWeights/applyStickyParams 方法；或把热更参数独立为 atomic 成员

### P1-C: TPS 机制双重失真
1. **计数失真**: `OQM::updateOrders` 正常路径恒返回 1（OptionQuoteManager.cpp:211），cancel_only 路径返回累计 m_numCancel → 撤单瞬间打爆配额、正常报价系统性低估
2. **窗口重置位置错误**: `m_txCount` 只在 `refresh()` 按 1s 清零 (ControllableTradingGrid.cpp:346-350)，但 refresh 在标的静止时不执行（shouldCompute=false）→ 窗口永不重置 → **永久 cancelOnly 死循环**
- **方案**: OQM 返回真实笔数（双腿+N撤单）；窗口重置移到 `drainPendingQuotes()`

### P1-D: GVV 双曲线混合退化
- **位置**: OptionPricer2.cpp:214-215 + PeriodicCurveFitter.cpp:289-290
- **根因**: `m_spVolCurve` 与 `m_spVolCurve2` 都是 GvvVolCurve，doFit 用同一份数据点拟合 → `vol ≡ vol2`，`volcurve_weight` 数值上无效。根因：`updateGvvParams` 是空 stub（OptionPricer2.cpp:228-237），参数化曲线永远收不到外部参数
- **方案**: curve1 接外部参数注入（setGvvParams 已有接口，需从 config 读取 spotvol/rho/volvol/alpha）

### P1-E: GammaScalp 期货报价粒度错误
- **位置**: GammaScalpOptionPricer.cpp:159
- **根因**: `tick_size = config.minUnderlyingSpread`（把价差当 tick 用，标的报价按 0.0002 粒度而非 1）
- **方案**: 从 commInfo 注入 tick_size

### P1-F: 双 panic 源语义冲突
- **位置**: HftOptionStrategy.cpp:316-320 vs 1104-1114
- **根因**: FillPriceChecker panic 回调写 `_traderCtx->panicked=true`，但 on_batch_complete 每 compute 用 `_pricer->isPanacked()` 覆盖 → FillPriceChecker 的 panic 下个 cycle 被自动清除
- **方案**: panic 源合并为 OR 逻辑：`ctx->panicked = pricer->isPanicked() || fillChecker.isPanicked()`

### P1-G: secondaryHedgeCodes 支持仅 30%
- **位置**: OptionRisk.cpp:125-142
- **根因**: `registerHedgeInstrument` 只入 `m_hedgeDataList`，`addSecondaryHedge`（OptionExpiryGreeks.h:118）无调用点 → 次级腿持仓 delta 不参与组合净额；不建 UTD、无报价
- **方案**: 接入 ExpiryGreeks 次级列表 + 建 UTD（工作量较大，可延后）

### P1-H: frac_delta 临期衰减未配置
- **位置**: ExpiryData.h:187
- **根因**: `setExpireDeltaFrac` 全文无调用点 → 临到期时 gamma/vega/theta 衰减但 delta 永不衰减
- **方案**: initValuesCompute 中根据 maturity 计算并 setExpireDeltaFrac

## 三、性能优化（按 ROI 排序）

### PERF-P0: 编译优化（最大单项收益）
- **位置**: CMakeLists.txt — 无任何 -O flag（实际构建为 -O0！）
- **方案**: 加 `-O3 -march=native -flto`；评估 `-ffinite-math-only` 替代 `-ffast-math`（保 NaN 语义）
- **预期收益**: 数值路径 2-5x（FAST cycle 2.7ms→~0.8-1.4ms）

### PERF-P1a: 唤醒改 busy-spin + 绑核
- **位置**: OptionAsyncEventProcessor.cpp:247 (condvar wait_for 100us)
- **现状**: 唤醒延迟 5-30us（P99 100us+），CFS 调度未绑核
- **方案**: worker 线程 SCHED_FIFO + CPU 亲和性绑核；空载时 spin(pause) + 定期 cv fallback
- **预期收益**: 唤醒 <1us，消除 P99 尖刺

### PERF-P1b: GVV eval 优化
- **位置**: GvvVolCurve.cpp:145-172
- **现状**: 每次 eval = Brent 求根 10-100 迭代（0.5-4us），且 weight=0 也两条曲线全算
- **方案**: weight=0 短路（只算 curve2）+ per-cycle (strike,fwd) 记忆化 + 查表+插值替代在线求根
- **预期收益**: SLOW cycle -50%~-80%（-2~-10ms）

### PERF-P1c: 增量定价
- **位置**: CompositeOptionPricer.cpp:302-410 (FAST 全量遍历 1816 合约)
- **方案**: dirty bitmap 标记（onTick 时标 strike，forward 变化时标 expiry），FAST 只重算变化合约
- **预期收益**: FAST cycle -60%~-90%

### PERF-P1d: 消除冗余查找
- **位置**: OptionPricer2.cpp:552 (grid->get 找已持有的对侧腿) + cpp:353 (thread_local map)
- **方案**: computeValue 接收 StrikeData（已有双腿）；thread_local map 改 OptionData::m_internalId 数组索引
- **预期收益**: SLOW cycle -1~-1.5ms

### PERF-P1e: getMaturity 缓存
- **位置**: ExpiryData.cpp:95-126
- **现状**: 每合约每 cycle 调用，内含 localtime() (~50-100ns，glibc tz 锁)
- **方案**: 每 expiry 每 cycle 缓存一次（在 initValuesCompute 中预算）
- **预期收益**: FAST cycle -0.3~-0.6ms

### PERF-P1f: attrPub collect 节流
- **位置**: AttributePublisher.cpp:15-37
- **现状**: 每 batch 全量 map 查找 1816 合约 ≈ 0.4-0.9ms，即使 publish 被 1.5s 节流
- **方案**: collect 随 publish 节流；map 改数组（internalId 索引）
- **预期收益**: 每 batch -0.4~-0.9ms

## 四、架构改进

### ARCH-1: OptionPricer2 ⇄ PeriodicCurveFitter 循环 shared_ptr
- **位置**: OptionPricer2.h:252 + PeriodicCurveFitter.h:99
- **现状**: 靠空 deleter `shared_ptr<OptionPricer2>(this, [](OptionPricer2*){})` (OP2.cpp:162) 破解循环；同一 fitter 被 grid/pricer/strategy 三处持有
- **方案**: Fitter 持 OP2 裸指针或 weak_ptr；OptionGrid 移除 m_fitter/m_optionPricer（数据层职责越界）

### ARCH-2: 三条并行执行路径（仅 1 条有风控）
| 路径 | 风控 | 决策 |
|------|------|------|
| CTG/OQM 做市单 | ✅ RiskFilterChain + PositionGuard + TPS | 保留 |
| Scanner taker 单 | ❌ 无风控 | **分离**：taker 单更激进，仅补 PositionGuard（防打穿总仓位），不加 RiskFilterChain |
| GammaScalp 对冲单 | ❌ 无风控 | **分离**：仅补 PositionGuard（防对冲超量），不加 TPS 限制（对冲不能等） |

### ARCH-3: 持仓无单一事实源
- **现状**: OptionData::m_position / OptionRiskData::m_position / OQM::m_position / PositionGuard internal+broker / PositionOffsetMgr local+broker = 5+ 份拷贝
- **方案**: OptionRiskData 为准（唯一 write 点 = addFill + broker 同步），OQM/OD/PositionGuard 从它读

### ARCH-4: 死代码层清理
- OTD/UTD 的 3 个 executor hooks（OptionTradingData.h:87-89）— 绑定但从不调用
- OptionData 双缓冲 beginUpdateValues/commitUpdateValues（h:115-117）— 无人调用
- addDataListener/notifyMarketsPriced 链（h:149-164）— 无消费者
- CTG m_optUpdateSet（h:142）— 只写不读
- OTD::getPosition()（cpp:95-103）— 链路断裂恒返回 0
- IOptionPricer 胖接口 ~15 纯虚 — 应拆 ITheoPricer + IQuotePricer

### ARCH-5: ExpiryData::m_hedgeUTD 裸指针
- **位置**: ExpiryData.h:116-118,167 ⇄ UnderlyingTradingData.h:216
- **现状**: 数据层持交易层裸指针，生命周期依赖 OTG 存活
- **方案**: 改 weak_ptr 或通过 OTG 查询接口
